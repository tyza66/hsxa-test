# 答案文件格式硬约束

依据 `docs/README.md` 与 `docs/答题模板.txt` 整理，`scripts/validate.py` 逐条实现了本文的每一项检查。
提交前必须过一遍校验器，**不通过就不要提交**——格式问题的代价是整份答案被拒，而不是扣几分。

## 顶层结构

答案文件是一个 JSON 对象，恰好三个键，多一个少一个都算失败：

顶层三键是 `选手名称`、`参赛包编号`、`答案`。

`参赛包编号` 必须与参赛包里的编号一致，从 `docs/参赛包.txt` 抄，不要凭记忆写。

## 答案数组

`答案` 是非空 JSON 数组，每个元素恰好两个字段 `题号` 与 `查询语句`，不允许再带说明、置信度或备注。

题号形如 `M001-S009`（三位题组号加三位题号），且必须与题目清单完全一致：

- 缺题、多题、题数不等，整份拒绝；
- 重复题号，整份拒绝；
- 出现题目里没有的题号，整份拒绝；
- 顺序不要求一致，但按题目顺序排布最省心。

## 查询语句取值

分两种，没有第三种：

1. 能转换：填一条最终 FOFA Query，例如 `app="gitlab"`、`(country="CN" && port="443")`；
2. 不能转换：填固定串 `该需求不能直接转换为FOFA搜索语句`，一字不差。

以下写法都会被拒或不得分：

- 空串、纯空白；
- 多条语句拼在一起、或用换行分列多条候选；
- Markdown 代码块包裹（出现三个反引号即判失败）；
- 查询前后带解释文字；
- 首尾有多余空白。

另外，非固定串的查询必须通过 `scripts/lookup.py` 的 `lint` 语法体检：全角符号、括号引号不配对、
Unique IP View 字段与其他语法混用这类低级错误要在提交前拦掉。

## 文件编码与体积

- UTF-8 编码，允许 BOM；
- JSON 而非 JSONL；
- 不超过 8 MB；
- 不得包含账号、密钥或未经授权的数据。

## 自检

```bash
python3 skill/scripts/validate.py skill/answers/答案.json --参赛包编号 pkg-08e82c8d
```

输出 `结果: 通过` 才算数。任何一条拒绝原因都对应本文的一节，按图索骥改完重跑。

## 交付物路径

| 文件 | 角色 |
| --- | --- |
| `skill/answers/答案.json` | 本 Skill 为本参赛包生成的答卷 |
| `skill/tests/golden.json` | 答卷的 golden 快照，回归对账用，勿手改 |
| `skill/tests/convert.json` | 机械层快照，回归对账用，勿手改 |
| `skill/tests/review.md` | 中低置信度待确认清单 |

`validate.py --题目` 指向 `docs/题目.txt`。`docs/` 与 `rules/` 只读，`test/` 归用户管理。
